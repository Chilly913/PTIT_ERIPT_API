# PostgreSQL schema conventions (PTIT_ERIPT_API)

The schema is redesigned from scratch for PostgreSQL 17. The legacy MySQL schema
(85 incremental Laravel migrations) is kept only as reference in
`docs/db/legacy_mysql_schema.sql`. Seed/data migration is out of scope for now,
but every design note must record the old -> new mapping so data can be moved later.

The public HTTP API (JSON shapes consumed by frontend + mobile) must stay
reproducible from the new schema. Optimise the storage, not the contract.

## Files

- Tool: golang-migrate. Files: `migrations/NNNNNN_<name>.up.sql` and `.down.sql`.
- Ownership (one owner per file, never edit another domain's file):

| File | Domain |
|---|---|
| `000001_base` | extensions, helper functions |
| `000002_identity` | users, auth, RBAC, org units |
| `000003_learning` | catalog, courses, lessons, enrollments, progress, Q&A, reviews, assignments |
| `000004_academic` | academic years, terms, programs, curricula, outcomes, administrative classes, class sections, schedules, offline sessions + attendance |
| `000005_assessment` | question banks, questions, quizzes, attempts, exams, proctoring, gradebook |
| `000006_commerce_career` | orders, vouchers, tuitions, points, career paths, certificates, jobs, CVs, recommendations |
| `000007_system` | notifications, news, site settings, AI settings/logs, surveys |
| `000090`+ `_deferred_fks_<domain>` | FKs that point to a table in a LATER-numbered file (each file needs its own version number: 000090 identity, 000091 learning, next free number for new ones — golang-migrate rejects duplicate versions) |

A file may only reference tables in itself or in lower-numbered files. If you need
an FK to a later file's table, create the column without the FK and put the
`ALTER TABLE ... ADD CONSTRAINT` in your own `000090_deferred_fks_<domain>` file.

Each `.down.sql` drops exactly what its `.up.sql` created (`DROP TABLE IF EXISTS ... CASCADE` in reverse order).

## Types

| Concern | Rule |
|---|---|
| Primary key | `id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| FK columns | `bigint`, always indexed (unless covered by a leading column of another index) |
| Strings | `text`; add `CHECK (char_length(x) <= N)` only for a real business limit |
| Emails / usernames / codes compared case-insensitively | `citext` |
| Enum-like | `text NOT NULL` + `CONSTRAINT ck_<table>_<col> CHECK (col IN (...))` (no PG enum types) |
| Booleans | `boolean NOT NULL DEFAULT ...` (never smallint) |
| JSON | `jsonb` |
| Money (VND) | `numeric(14,2)` |
| Scores / percentages | `numeric(5,2)` or as appropriate |
| Timestamps | `timestamptz`; `created_at timestamptz NOT NULL DEFAULT now()`, `updated_at timestamptz NOT NULL DEFAULT now()` + trigger `set_updated_at()` |
| Date only | `date`; time of day: `time` |
| Media/file paths | store object key (relative), not absolute URL |

## Naming

- Tables: plural snake_case. Pure join tables: `<a>_<b>` (singular_plural as reads naturally, e.g. `user_roles`).
- Constraints: `pk_`, `fk_<table>_<column>`, `uq_<table>_<cols>`, `ix_<table>_<cols>`, `ck_<table>_<col>`.
- FK `ON DELETE`: choose deliberately — `CASCADE` for owned children, `RESTRICT` for references to master data, `SET NULL` for optional links (e.g. `created_by`).

## Helpers provided by `000001_base`

- Extensions: `citext`, `pg_trgm` (use GIN trigram indexes for search columns that the API filters with LIKE/ILIKE).
- `set_updated_at()` trigger function. Attach with:
  `CREATE TRIGGER trg_<table>_updated_at BEFORE UPDATE ON <table> FOR EACH ROW EXECUTE FUNCTION set_updated_at();`

## What to drop

Laravel framework tables are NOT recreated: `migrations`, `cache`, `cache_locks`,
`sessions`, `jobs`, `job_batches`, `failed_jobs` (Go uses Redis/asynq).
Spatie polymorphic tables become plain user-based tables (`model_type` disappears).

Drop a table or column only with evidence (no reads/writes in `backend/app`, no
frontend dependency in the API output). Record every drop with the reason.

## Design notes (required per domain)

`docs/db/<NN>_<domain>.md` containing:
1. Table list with one-line purpose.
2. Changes vs legacy: renames, merges, splits, dropped tables/columns (with evidence), new constraints/indexes and why.
3. Old -> new column mapping table (for the future data migration and the Go port).
4. Open questions.
